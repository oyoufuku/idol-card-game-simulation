# CPU・構築・田村Bの更新（2026-10-13）

カード変更は田村保乃Bのチャット確定差分だけ。他47人と全22曲の性能・数値、通常CPU/CHARGE CPUの評価式・乱数方式は変更しない。新たな勝率改善は未測定。大規模Cloudシミュレーションは行わない。

## 田村保乃Bの確定差分

条件と抽選対象は相手BACKSのBURST開始を維持する。同じ終了処理で該当する相手からランダム1人を選び、次のパフォーマンス終了までCENTERに固定し、Bスキルのみ無効化する。元CENTERはBACKSへ移動。A/Cは有効、Appeal減少は付けない。終了時の通常BURST条件と強制BURSTのB効果も無効。強制BURSTの共通疲労0・発動履歴は記録する。

完了済みの疲労・チャージ回復、移動、属性追加、楽曲変更、永続基礎補正、通常使用済み状態・累計BURST回数は巻き戻さない。Bの継続加算・引継ぎ・全体補正などを停止する。既存の免疫・位置固定を優先し、抽選後の別対象への選び直しは行わない。UI・通常preview・CPU・CLIは同じスキル無効処理を使用する。

## 追加CPU

`--cpu-strategy burst`／開始画面「BURSTを考慮」で選択する。通常とCHARGEは維持し、既定の通常CPUを自動変更しない。

本番engineで公開ラウンド開始状態を複製し、今回の終了処理・疲労・通常/強制BURST・連鎖を処理する。相手は公開済み基準配置のまま。未確定配置、非公開楽曲順、実試合の乱数状態、手動対象は参照しない。

評価値は、今回の「符号付き得点×12＋勝敗×2＋Appeal差×0.25」に次回平均の0.6倍を加える。R6では次回ENCORE後の予測最終勝敗×40を加える。今回の予測敗北で数学的に取り返せなくなる候補を優先的に避ける。疲労は実Appeal・次回状態を通して評価し、一律の減点を加えない。同評価時だけ終了時疲労とseed付き抽選を使う。R7は次回価値0・同じ探索設定の通常CPUと同じ選択。

公開された選択3曲×2と使用曲から次曲候補を作り、特殊曲は通常カードを減らさない。ENCOREは予測の劣勢側の3曲・同点時両側から。既知のB楽曲変更もengineで反映する。重複曲は確率の重みとして扱い、同じ曲の計算は再利用する。

次回は配置維持、ステージ交換、BACKS単独/2人/3人の限定同時投入（最大86候補）を評価する。3人同時投入を含めることで村井とチャージコアを1人交換だけで過小評価しない。相手の次回編成最適化やR1からR7までの探索はしない。

既定は二段階・100候補。一次評価は今回の全合法候補をengineで終了まで計算し、公開次曲1候補・持ち越し配置で概算順位を作る。上位100候補で全公開次曲候補と限定した次回配置を比較する。未知の曲・抽選・相手配置・候補絞り込みによる誤差があり、全探索の最適解や実際の勝率ではない。normal/chargeの既定探索は不変。

`burst_cpu_round_trace.csv`は予測、既存`charge_round_trace.csv`は実測。新予測CSVはanalysis.xlsx・analysis_bundle.jsonにも入る。実試合のseed系列は予測で消費しない。

## 戦術を優先した27チームの見直し

9タイプ×3＝27チームを維持。構築済み12デッキ案は別枠で、27チームを置き換えない。

既定 `balanced` は `tactical-role-coverage-v2`。先に戦術・能力対象・属性・ポジション条件を確認して支援候補と役割を決め、その範囲で起用を分散する。強い軸はクール/多属性/疲労回復の既存3コアを保ち、優勢・劣勢・防御・疲労管理などの条件付き支援を試す。チャージ/移動/対スキルは序盤の得点、CENTER候補、出場を支える疲労対策を厚くする。これらは事前の役割方針であり、勝率・WARをスコア入力にしない。

- クール：森田・清水の多属性条件をクール構築支援と混同する加点を修正。森田はクール候補から除外。
- チャージ：渡邉美穂・渡辺莉奈・平尾帆夏を固定。Aは山下瞳月、Bは小坂、Cは金村を序盤/投入時の支援役にする。残り支援は自軍BACKSを主要条件にせず、竹内だけ例外。
- 移動：山下葉留花・村井・小西のコアを維持。松田里奈・向井・増本・村山を支援候補から外し、Aは井上による回復、Bは守屋への疲労連携、Cは山下瞳月のCENTER得点を補う。
- バースト：自軍連鎖の中嶋・松田里奈・森本を核にする。低BURSTで強い好花、対BURSTの田村は入れない。
- 多属性：8人の3属性だけでなく、各属性2人以上を確保しステージ3属性とBACKS3属性を同時に成立可能にする。谷口のキュート上書きを入れない。平岡がいる場合は選択曲も3属性にする。
- 対スキル：A/Cは田村の相手BURST反応を活かすためJOYFUL LOVEと自軍Cを止める静寂の暴力を避ける。Bは好花とJOYFUL LOVEによる低BURST運用。村井の登場保護は全候補に維持。
- メタ：小田倉・河田と既存profileの核を維持。PLAINと属性人数参照は同時に足さずCENTERを切り替える。

全チームの採用数の平方和が減る差し替えだけを行い、最初の役割構築スコアから低下4以内に制限する。コアと明示した固定支援、属性条件、候補内8人の重複なし、同じ軸の候補ごとの異なる8人セットを維持する。曲は変更後のメンバーに対する実効果と役割で再評価する。

`legacy` は旧方式の全カード/曲/理由/seedを保持する比較用。旧カード性能の復元ではない。旧結果を新構築のcheckpointへ混ぜず、別の出力先で開始する。RANDOM構築と通常CPU/CHARGE CPUの判断は変更しない。

seed 1：全48人を起用、採用数は1〜7チーム。起用均等化より役割を優先するため、好花は解除型1候補、田村は封殺型2候補に限る。ステージ出場率の均等や勝率改善は未検証。
