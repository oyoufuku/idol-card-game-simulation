# CPU評価の確認（2026-10-08、変更前の記録）

**更新**：このレビューを受け、共通CPUを「得点→勝敗→Appeal差→終了時疲労」に修正済み。公開済みスナップショットのみを参照し、覗き見防止と妨害評価の回帰テストを追加した。以下は修正前の問題点の記録。現行仕様は [README](README.md) を参照。

ユーザーの追加指示により、バランスシミュレーションの試運転・本格実行は未開始のまま保留。
今回の48人・22曲対応、CLI、統計処理は作業中であり、テスト・完成判定前。以下はコードの静的確認結果。

## 現行方式

`src/game/cpu.ts` の既存版と作業中の共通評価関数はいずれも、合法な8P5（最大6,720）配置を評価し、自チームの予測総Appealを最大化。同値なら自チームの概算終了時疲労を最小化する。作業中の版は完全同値時に注入PRNGで選択する。

`preview` は共通エンジンの両チームのAppealを計算するが、CPUの比較キーには相手Appeal・Appeal差・予測得点・勝敗が含まれていない。したがって相手だけを弱体化する能力を積極的に選ぶ理由がなく、バランス検証には不適切。

## 評価できない／不十分な能力

- 相手Appeal低下：石森、小田倉、谷口、遠藤理子BURST、幸坂、田村、森田、守屋、上村、清水、藤嶌、渡辺莉奈、丹生、河田など。相手に発生した損失自体は評価されない。
- 相手ポジションボーナス無効：宮地AUTO/BURST、石塚BURST。
- 相手への疲労付与：大沼、増本、石塚、平尾など。そのラウンドに相手Appealを落としても、それ自体は評価キーに入らない。次ラウンド以降の蓄積価値も評価しない。
- 属性変更・PLAIN：小田倉BURST、藤嶌CENTERなど。相手の属性条件や相手の楽曲加算を崩す価値が抜ける。自軍の加算・被害軽減へ波及する分だけ間接的に評価される場合がある。
- AUTO/CENTER無効：的野など。敵の自強化を消す価値は抜ける。自軍への妨害を消し、自軍Appealが上がるケースは評価される。
- 位置固定：的野、幸坂、田村。既にある固定は合法配置の制約として守るが、相手の将来の選択肢を奪う価値・最適対象は配置評価しない。対象選択は別の単純ヒューリスティック。
- BURST READY：条件を狙って配置する将来価値は評価しない。既に発動しているBURSTの自軍Appeal効果だけは計算に入る。
- チャージ：今使うチャージが自軍Appealへ反映されれば評価される。BACKSで蓄える価値、回復、将来の使い時は評価しない。相手弱体化型のチャージは不利。
- 位置維持、シンメ履歴、楽曲履歴、BURST回数：現在のAppealへ反映される部分だけ評価。将来の条件達成価値は評価しない。
- 疲労回復：現在の自軍Appealに反映される分と同値時の概算疲労のみ。長期的な消耗戦の価値は評価しない。

疲労見積もりも完全な終了処理ではない。位置疲労・BACKS回復・一部AUTO軽減を概算し、キツネ、BURST終了時の疲労追加、敗北時CENTERなどの終了処理全体を再現していない。

## 情報の可視性

既存ブラウザCPUは現在のP1配置を直接参照する。1台用UIではプレイヤーが配置を編集した後にCPUボタンを押すため、同時秘密配置の公平性は保証していない。
作業中CLIは両者の配置を同一スナップショットから独立評価してから一括適用し、相手CPUが今回選んだ配置を参照しない。ただし情報公開ルールに合わせ、ゲーム本体でも公開済み配置のスナップショットを明示的に使用する必要がある。

## 次の修正範囲（まだ適用していない）

高度な先読みを追加せず、同じ公開情報に対して以下を辞書式比較する。

1. 共通スコア処理によるそのラウンドの予測獲得ポイント
2. 予測勝敗（勝利 > 引き分け > 敗北）
3. 自チーム予測Appeal − 相手チーム予測Appeal
4. 予測終了時疲労（小さい方）
5. 完全同値ならseed付きPRNG

終了時疲労は共通の終了処理と整合させ、乱数を勝手に消費しない。未来のBURSTやチャージに独自の重みを付ける変更はこの修正に含めない。

相手未確定配置を変えても自分のCPU判断が変化しないテスト、および自軍Appealだけが高い配置より敵のAppealを落として勝つ配置を選ぶ回帰テストが必要。
