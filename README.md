# アイドル対戦カードゲーム テストプレイ

このリポジトリは、GitHub Actionsでバランス検証するためにPrivate開発リポジトリのmainから作成した公開用スナップショットです。過去のGit履歴を含まず、公開後のコミット作者にはGitHubのnoreplyアドレスを使用します。

最新同期：Private mainのPR #42（2026-10-17）。大園Aを自身へのマイナス無効へ変更し、光莉・濱岸のBへ次回本人Appeal+2を追加。対スキルはPR41前の編成へ戻し、クールは8人全員クールを維持。正確なsource commit・仕様fingerprint・各ファイルhashは `SIMULATION_SOURCE.json` に記録します。

Actionsの **Constructed decks and RANDOM through L1** は、構築済み各組合せ50戦（計3,900戦）とRANDOM1,000戦を別runnerで並行実行し、両方の入力・checksumを検証して合流後、L1だけ実行します。L2/L3は自動開始しません。ゲーム・CPU・分析処理はマージ済みソースと同一で、この専用workflowだけ公開環境の運用ファイルです。

React + TypeScript + Vite製のカードゲームです。現在は `案_48人22曲_Codex実装用_最終確定_20261011.xlsx` のメンバー48人、楽曲22曲を収録。最新の「Codex用メンバー」（修正シートも同一）を既存データに上書きしています。CPU戦と1台でのローカル対戦に対応し、通信対戦は未実装です。旧原本HTMLは履歴として変更せず保存しています。

## PCですぐテストプレイ

このブランチをGitHubの「Code → Download ZIP」でダウンロードして解凍し、`testplay/index.html` をChrome・Edge・Firefox・Safariなどの新しいブラウザーで開いてください。ダブルクリックでも起動できます。Node.js・pnpm・Python・サーバーは不要です。

横持ちUI・BURST演出付きのCPU戦と同じPCでの手動対戦に対応します。通信対戦は未実装です。ブラウザーを再読み込みすると試合はリセットされます。

画面上部の「全画面」をタップすると、対応ブラウザーではアドレスバーを隠して遊べます。「全画面を終了」またはブラウザー・端末の戻る操作（PCではEsc）で戻せます。試合はそのまま続けられます。Androidの `content://` など、ブラウザーやファイルの開き方によっては全画面を利用できない場合があり、その際は画面に案内を表示します。

開発時は `pnpm build:testplay` で、この単一HTML版を最新のソースから再生成できます。

## 起動

Node.js 22以降とpnpmを用意し、リポジトリで実行してください。

```sh
pnpm install
pnpm dev
```

表示されたローカルURL（通常 `http://localhost:5173`）を開きます。各プレイヤーのアイドル8人・楽曲3枚を選択して開始します。CPU戦では配置を変更した後に「CPU配置を決定」を押してください。CPUは公開済みのラウンド開始配置だけを参照し、今回のプレイヤーの配置変更は見ません。BURSTはパフォーマンス終了時に条件を満たしたカードから1枚ずつ発動します。小島・的野・幸坂・松田好花とチャージ3人の対象は各カードの発動直前に選択します。

```sh
pnpm test     # 最新Excelのルール検証・旧版の共通処理比較
pnpm build    # strict TypeScript型チェック＋本番ビルド
pnpm preview  # distのプレビュー
```

依存バージョンは `pnpm-lock.yaml` に固定しています。Windowsでリンク権限を要求しない構成を `.npmrc` に保存し、必要なesbuildのセットアップだけを `pnpm-workspace.yaml` で許可しています。

## 横持ちカードUI

スマートフォンの横画面を前提に、ステージ5枚を MIDDLE L / FRONT L / CENTER / FRONT R / MIDDLE R の横一列で表示します。FRONTは少し前、CENTERはさらに前に出ます。横持ちではBACKS3人をステージの横に並べます。ステージの5枚は同一の固定サイズ、BACKSの3枚も同一の固定サイズで、ステージ側を一回り大きく表示します。名前・画像枠・能力欄は共通の2:3カードテンプレートを縮尺に合わせて表示し、能力文の長さでカードが伸びることはありません。盤面では名前と画像を確認し、能力全文は左側の詳細をスクロールして読めます。横向きでは左側を拡大カード専用の領域として常に確保します。右側に楽曲・CENTER SKILL・総Appeal・盤面・操作ボタン・相手確認・対戦ログをまとめます。左右は独立してスクロールでき、左のカードを見たまま右の配置枠を操作できます。配置・CPU・パフォーマンスの操作ボタンは自分のステージの見出しにまとめ、盤面の上へ大きなボタンを重ねません。楽曲効果は見出しを開いて読めます。演出設定は開いてもヘッダーの高さを広げない表示です。対戦ログやカード一覧も盤面側の幅に収めます。縦向きでも操作できますが、横向きへの案内を表示します。

編成画面では、P1とCPU/P2のそれぞれに「手動選択」「ランダムピック」「アーキタイプ」を選べます。ランダムはアイドル8人・楽曲3曲を選び、「引き直す」で再抽選します。アーキタイプはシミュレーターと同じ9テーマ・各3候補を用意し、メンバー能力・楽曲効果を確認できます。自動で選んだ編成は「この編成を手動で調整」で変更できます。

カードは縦長で、上から名前・基礎Appeal、横長の画像枠、Aスキル・B条件・Bスキル・Cスキルを並べます。画像は未収録です。盤面では能力文を短く表示し、左の拡大カードでは全文を読めます。現在の属性をクール＝青・キュート＝ピンク・ユーモア＝金で表し、2属性は2色、3属性は3色のフレーム、PLAINは灰色になります。属性表示は共通エンジンの現在のパフォーマンス予測に従い、属性追加・変更・PLAINの優先も反映します。原本HTMLは未変更です。現在のカード・楽曲の値とスキル処理はExcel更新版の仕様に従います。

パフォーマンスのスキル演出はP1のMIDDLE L → MIDDLE R → FRONT L → FRONT R → CENTER、各カードA → B → Cの順に表示し、その後P2、控え、終了時効果を表示します。実際に適用されたAppeal・疲労・チャージなどの変化を対象カードの上に表示し、数値増加は赤い上矢印、減少は青い下矢印で動きます。終了時BURSTの即時B効果も1枚ずつ処理・表示します。小島・的野・幸坂・松田好花とチャージ3人の対象は各カードの発動時に選択します。継続B効果のAppeal変化はパフォーマンス時に表示します。演出中は操作を止め、「演出をスキップ」で再開できます。A/B/Cの表示は共通エンジンで計算した変化を順番に再生します。BURSTタイミングは2026-10-09のユーザー指示で変更しています。CPU候補評価では演出記録を作りません。CLIの実試合ではチャージ回復統計のために共通の効果記録を使用します。

複数人へ同じ種類の効果が及ぶ場合は「全員」「自チーム」「相手チーム」「自/相手チームのBACKS全員」「ステージ全員」などの1つのメッセージにまとめ、実際の対象カードへ同時にエフェクトを表示します。属性追加前からその属性を持つ人・無効化された人・チャージ上限の人など、状態が変わらなかったカードには変化を表示しません。一部だけが対象なら対象人数を表示し、疲労の下限などで数値が異なるときは実適用値も併記します。

画面上部の「演出設定」で「演出を自動で進める」をON/OFFにできます。上部のスキルメッセージとBURST演出中にも切り替えられます。初期値はONで、OFFでは「次へ」を押すまで説明やBURST待機が進まず、BURSTの反転後のカードも画面に残ります。対象を選ぶスキルは引き続き対象選択が必要です。設定は保存可能なブラウザーでは次回起動にも引き継ぎます。ゲームの計算・乱数・CPUには影響しません。

配置中は相手の前回の公開済み配置（R1は初期配置）を対面向きに反転して自分の盤面の上に表示します。相手の未確定編集は表示せず、パフォーマンス後は確定配置を表示します。相手BACKSは初期表示から3人のカードを開いて表示し、タップで詳細を確認できます。BACKSの見出しで折りたたむこともでき、演出の対象になった時には自動で開きます。配置枠のIDや対面効果のルールは変わりません。スマホでは盤面・操作をデスクトップの約75%（以前の50%表示の1.5倍）に調整しています。横持ちの左の拡大カード枠を広げ、右の盤面とBACKSも利用可能な幅を使い、左右の余白を抑えます。カード詳細と盤面はそれぞれスクロールできます。

スキルは画面最上部の横長メッセージ帯で発動者告知（約2.6秒）→対象カードごとの効果説明（各約3.2秒）と進み、右から左へフェードします。ヘッダー・演出設定に重ねて表示し、盤面にかかる分だけ余白を確保します。対象カードが盤面の表示領域の中央付近に来るようにスクロールします。長い能力文は「スキル効果を確認」で開けます。「次へ」で1件だけ送り、「スキップ」でその効果列を終えます。BURST反転中はBスキルの説明を待機し、反転後に開始します。端末の「動きを減らす」設定では静的表示になります。

Appeal内訳はP1/P2、発動者、A/B/C、楽曲名、効果全文、軽減・無効化後の適用値を表示します。増加は赤太字、減少は青太字。基礎・ポジション・疲労・下限補正も分け、内訳の合計が表示Appealになるよう記録します。表示用メタデータの追加であり、ルール・得点・CPU判断は変更しません。

シミュレーション専用のCHARGE CPUと「対単一属性メタ」3候補を追加しています。通常CPU・おすすめ配置の評価方式は維持します。Windowsコマンドは [SIMULATION.md](SIMULATION.md)、変更仕様と確認結果は [実装確認](docs/simulation/charge-review.md) を参照してください。

`--fast-simulation` でCLIの効果記録・チャージ詳細を省略できます。勝率・通常のカード統計を維持し、候補キャッシュ等の高速化は常に有効です。チャージ軸は渡邉美穂・渡辺莉奈・平尾帆夏の固定コア＋ステージ支援5人に更新しました。詳しくは [高速化・編成の確認](docs/simulation/fast-review.md) を参照してください。

追加高速化と任意の二段階CPU評価（上位100〜300候補）、BURST専用の特殊曲K/Sを反映しています。通常選択は20曲です。新しい実行・再開方法は [SIMULATION.md](SIMULATION.md#12-二段階評価で候補を絞る) を参照してください。
